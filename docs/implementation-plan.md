# План реализации

Основа — [техническое задание](../tz.md). Работа разбита на вертикальные срезы: после каждого этапа есть работающий и проверяемый результат.

**Пилот возможен после этапа 6 без email** — ссылки респондентам руководитель копирует и рассылает вручную. Почта, напоминания и дедлайны добавляются в этапе 7.

## Структура репозитория

```
backend/
  src/ReviewPlatform.Domain          — сущности, правила переходов, расчёты
  src/ReviewPlatform.Application     — команды/запросы MediatR, валидация, права
  src/ReviewPlatform.Infrastructure  — EF Core, Postgres, почта, фоновые задачи
  src/ReviewPlatform.Api             — эндпоинты, auth, OpenAPI
  tests/ReviewPlatform.Domain.Tests  — unit-тесты расчётов и статусов
  tests/ReviewPlatform.Api.Tests     — интеграционные тесты (Testcontainers)
frontend/                            — React SPA (admin + survey)
seed/                                — начальная матрица
docs/                                — документация
docker-compose.yml
```

## Этапы

### Этап 0. Каркас (S)
- Solution из 4 проектов и 2 тестовых, `Directory.Build.props` (nullable, warnings as errors), `.editorconfig`.
- Vite + React + TS strict, Tailwind, shadcn/ui, роутинг `/login`, `/admin/*`, `/survey/:token`.
- `docker-compose.yml`: postgres, mailpit, backend, frontend. Health-check `/health`.
- CI (GitHub Actions): сборка, тесты и линтер для backend и frontend.
- Генерация TS-типов из OpenAPI (`openapi-typescript`).

**Готово, когда:** `docker compose up` поднимает пустое приложение, CI зелёный.

### Этап 1. Домен, БД и матрица (M)
- Сущности матрицы и справочников, первая миграция; миграции применяются при старте. Остальные сущности раздела 5 ТЗ добавляются в тех этапах, где появляется их поведение (сотрудник — 2, сессии и респонденты — 3, ответы — 4, решение — 6, outbox — 7).
- Справочники: грейды, роли, правила ролей по грейдам; импорт `seed/backend-matrix.xlsx` при первом запуске.
- API матрицы на чтение: `GET /api/tracks/{id}/matrix`, `GET /api/grades`.
- Экран «Матрица» в админке: таблица «группа × грейд», только просмотр.

**Готово, когда:** после запуска в UI видны 160 индикаторов.

### Этап 2. Аутентификация, пользователи, сотрудники (M)
- ASP.NET Identity, JWT access/refresh, роли Admin и Manager; первый Admin из конфигурации, смена пароля при первом входе.
- Проверка прав в Application-слое: Manager видит только своих сотрудников и сессии.
- CRUD пользователей и сотрудников (API + экраны), карточка сотрудника.
- Интеграционные тесты прав доступа.

**Готово, когда:** Admin заводит руководителя, руководитель входит и видит только своих сотрудников.

### Этап 3. Сессии: создание и запуск (L)
- Мастер: сотрудник → тип (Transition / Confirmation) → дедлайн → респонденты с проверкой правил ролей → предпросмотр анкеты.
- Черновик: сохранение, редактирование, удаление.
- Запуск: снимок индикаторов в `SessionIndicator`, выпуск токенов (в БД — хеш), ссылки для копирования.
- Статусы `Draft → InProgress`, `Cancelled`; одна активная сессия на сотрудника.
- Список сессий с прогрессом; карточка сессии: удалить/добавить респондента, перевыпустить ссылку.
- Unit-тесты переходов статусов.

**Готово, когда:** руководитель запускает сессию и получает рабочие ссылки.

### Этап 4. Опрос респондента (L)
- Публичный API: `GET /api/surveys/{token}`, `PUT .../draft`, `POST .../submit`; проверка токена и всех состояний.
- Mobile-first UI: предупреждение о видимости ответов, пошаговый проход по группам, кнопки 0–3 и N/A, комментарии, автосохранение с дублем в `localStorage`, экран подтверждения.
- Переход сессии в `AwaitingDecision` при сдаче последней анкеты; `xmin` + повторы; интеграционный тест на параллельную сдачу.
- Rate limiting на `/api/surveys/*`.

**Готово, когда:** несколько человек проходят опрос с телефона, сессия сама переходит в «Ждёт решения».

### Этап 5. Расчёты и отчёт (L)
- Расчёты раздела 6.2 ТЗ как чистые функции в Domain; unit-тесты всех граничных случаев (кворум, N/A, пустые группы, Confirmation).
- `GET /api/assessment-sessions/{id}/report`, режим «промежуточные результаты».
- UI: сводка с ориентирами, паутинка (Recharts), детализация с оценками по именам, зоны роста, спорные индикаторы, слепые пятна.
- Выгрузка отчёта в Excel.

**Готово, когда:** отчёт по тестовой сессии совпадает с ручным расчётом.

### Этап 6. Решение и план развития (M)
- Форма решения: итог, новый грейд, обоснование, пункты плана (из зон роста или свои).
- Переход в `Closed`, обновление грейда сотрудника, история в карточке сотрудника.
- Журнал аудита ключевых действий.

**Готово, когда:** работает полный цикл от запуска до решения. → **Пилот на 1–2 командах.**

### Этап 7. Уведомления и сроки (M)
- Outbox, фоновый отправщик с повторами, MailKit, шаблоны писем.
- Письма: приглашение, повторная отправка, завершение, отмена.
- Планировщик: напоминания (за 3 и 1 день), переход в `Overdue` с письмом руководителю, продление и досрочное закрытие; идемпотентность.

**Готово, когда:** цикл проходит без ручной рассылки ссылок.

### Этап 8. Редактирование матрицы (M)
- CRUD групп и индикаторов, drag-and-drop сортировка, архивирование.
- Импорт Excel с предпросмотром изменений, экспорт, шаблон.
- Редактор правил ролей по грейдам.

**Готово, когда:** Admin меняет матрицу без разработчика, идущие сессии не затронуты.

### Этап 9. Доводка к продакшену (S–M)
- E2E-тесты (Playwright): запуск → опрос → отчёт → решение.
- Serilog (JSON), rate limit на вход, CORS, секреты через env. Бэкапы БД — на стороне инфраструктуры, в проект не входят.
- Правки по итогам пилота.
